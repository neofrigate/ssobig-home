# 일일남매 추천 할인 안내 개선

작업 기준: origin/main `200881a2741328328d7dd479654ca871a3edf44d`.
운영 배포·신청 생성·고객 데이터 수정·메시지 발송 없이 로컬에서 검증했다.

## 변경

- 코드/신청자 전화번호 입력 후 450ms 대기하여 읽기 전용 추천 검증 API 호출. 기존 `validate_day_nammae_referral` RPC와 기존 서버 자격 규칙을 사용한다.
- 본인 코드, 잘못되거나 비활성인 코드, 이전 혜택 사용, 진행 중 신청, 프로그램 중단, 쿠폰 중복에 이유와 다음 행동을 안내한다. DB 원문이나 개인정보를 응답에 반환하지 않는다.
- 코드/전화번호/혜택 선택/유입경로가 바뀌면 기존 성공을 무효화한다. 요청 취소와 응답 유효성 확인으로 이전 응답의 덮어쓰기를 막는다. 검증 시간 초과·통신 오류는 신청을 차단하고 재확인을 제공한다.
- 추천 할인을 선택한 채 빈 코드·실패 상태로 다음 단계나 제출을 진행할 수 없다. 정상가는 명시적인 ‘추천 할인 해제 · 정상가로 계속’으로 전환한다. 코드는 해제 후에도 다시 선택하면 보존된다.
- 최종 서버 검증을 유지한다. 서버 거절 시 오류 코드를 보존하여 프로필로 돌아가 수정한다. `referralRequested`가 true인데 코드가 누락되거나 쿠폰도 있으면 업로드 전에 거절한다.
- 동일 화면 수동 재시도도 동일한 `client_request_id`를 사용하고 동시 제출을 막는다. 기존 서버의 원자적 중복 처리에 연결한다. 새 화면/새로고침을 넘는 요청 ID 보존은 이번 변경에 포함하지 않는다.
- 쿠폰 확인 통신 실패, 사진 서버 업로드 실패, 제출 결과 불명확 상태에 한국어 재시도 안내를 보완한다. 필수값/사진 형식·용량/마감 모달의 기존 안내는 유지한다.

## 검증 방법

- `node --experimental-strip-types --test test/day-nammae-referral.test.mjs test/day-nammae-application-integrity.test.mjs`
- `npx tsc --noEmit`, 변경 TS/TSX 파일 ESLint
- 로컬 dev 서버 포트 3107에서 `node --experimental-strip-types test/day-nammae-referral-browser.mjs`. Playwright와 Chrome이 설치된 환경 필요. 테스트는 모든 외부 요청을 차단하고 회차·추천 검증·최종 제출을 모킹한다. 실제 신청 서버로 전송하지 않는다.
- 브라우저 테스트 결과 이미지: `output/referral-qa/` (로컬 검증 산출물, Git 제외).
